= TLint web

Developer guide for the browser-based TLint playground: `tlint`'s validation logic, compiled to WebAssembly and wrapped in a small web app so people can lint a check without installing anything. For the CLI itself, see link:../TLint/README.adoc[TLint].

== Architecture

[source]
----
Rust (../src, this repo's `tlint` crate)
  -> www/src/lib.rs   thin wasm-bindgen wrapper around `tlint::validate`
  -> wasm-pack build  compiles it to wasm + generates JS glue in www/pkg/
  -> js/lint.worker.js  runs the wasm module inside a Web Worker
  -> js/index.js        UI: CodeMirror editor, buttons, calls the worker
  -> webpack             bundles everything + static/index.html
  -> dist/                the deployable static site
----

Linting runs inside a Web Worker rather than the main thread, so a large check doesn't freeze the UI while it's being validated. The worker exposes the wasm module's `lint()` function via https://github.com/GoogleChromeLabs/comlink[Comlink]; the main thread calls it like a normal async function.

Only three of `tlint`'s four validators run here, Expectation`, `Schema` and `Value`. The `Link` validator is left out since it needs outbound network access that doesn't make sense to run from a browser tab; see link:../TLint/README.adoc[TLint] for details.

== Prerequisites

* A Rust toolchain via https://rustup.rs[rustup], plus the wasm target:
+
[source,sh]
----
rustup target add wasm32-unknown-unknown
----
* `wasm-pack`: `cargo install wasm-pack`
* Node.js and npm.

There's no backend and no database, this builds to a static site.

== Getting started

From `www/`:

[source,sh]
----
wasm-pack build  # compiles Rust -> www/pkg/ (wasm + JS glue)
npm install      # installs JS dependencies, including the `tlint` wasm package itself via the `file:pkg` entry in package.json, run wasm-pack build first
npm run build    # webpack production build -> www/dist/
npm run serve    # webpack-dev-server with live reload
----

Re-run `wasm-pack build` whenever you change Rust code (in `www/src` or the main `tlint` crate); the JS dev server only watches JS/HTML/CSS.

`npm run build` produces `dist/`, a plain static site you can serve however you like, that's what `Dockerfile.www`'s `nginx` stage does.

== Project layout

[source]
----
www/
  Cargo.toml          The `tlint-wasm` crate.
  src/lib.rs          wasm-bindgen entry point wrapping `tlint::validate`
  pkg/                Generated by `wasm-pack build`. Gitignored.
  js/
    bootstrap.js      Async entry point webpack loads first.
    index.js          UI wiring: editor, buttons, draft persistence.
    lint.js           Spins up the worker, exposes it as a promise.
    lint.worker.js    Runs in the Web Worker, calls into pkg/.
    example.js        Sample check used by "Load example".
  static/index.html   The app's single HTML file.
  webpack.config.js
  dist/               Generated by `npm run build`. Gitignored.
----

== Features

* CodeMirror editor with YAML syntax highlighting.
* "Load example", inserts a synthetic sample check.
* Draft persistence, editor contents survive a page refresh (`localStorage`), cleared by "Reset".
* A side panel linking to the official https://www.trento-project.io/docs/wanda/specification.html#_anatomy_of_a_check[check DSL spec].

== Container image

[source,sh]
----
docker build . -t tlint-web -f Dockerfile.www
docker run --rm -p 8080:8080 tlint-web
----

Multi-stage build: a Rust image compiles the wasm package (with a separate stage fetching a matching `wasm32-unknown-unknown` std library), a Node image runs webpack, and the result is served by nginx. Base image versions are configurable via build args.
